# 技術白皮書：EARA-7 企業級智能體七層參考架構與五大治理象限

**Enterprise Agent Reference Architecture (EARA-7) & Five Governance Quadrants**

* **文件編號**：ARC-WP-EARA7-2026
* **架構版本**：v1.0（跨行業通用標準版）
* **適用對象**：企業技術長（CTO）、企業架構師（Enterprise Architect）、AI 平台工程團隊、資訊安全與合規治理委員會
* **架構定位**：供應商中立（Vendor-Agnostic）、雲原生與混合雲通用的生產級智能體系統參考藍圖

---

## 1. 執行摘要（Executive Summary）

隨著大型語言模型（LLM）從單純的文本生成走向具備工具調用（Tool Use）與自主決策能力的智能體（Autonomous Agent），企業導入生成式 AI 的核心矛盾已從「模型智商是否足夠」**轉移至**「系統在生產環境中是否可控、合規、經濟且可持續演進」。

在缺乏系統性架構治理的情況下，企業部署智能體往往面臨五大結構性風險：

1. **事實幻覺與領域越界**：模型依賴預訓練記憶臆測企業內部規則，或發表違反組織立場的言論。
2. **權限提升（Privilege Escalation）**：智能體以系統超級管理員身份執行外部工具，導致低權限用戶透過自然語言越權存取敏感業務資料。
3. **非信任輸入劫持（Indirect Prompt Injection）**：智能體讀取外部郵件、網頁或第三方文件時，將隱藏的惡意指令誤判為系統命令，觸發未授權的資金或資料變更操作。
4. **推算成本失控**：高併發場景下重複請求直接穿透至旗艦大模型，導致 Token 消耗與 API 帳單呈指數級攀升。
5. **變更退化黑盒（Regression Black Box）**：提示詞（Prompt）、知識庫切片或模型版本的微調缺乏全鏈路追蹤與自動化回歸測評，單次未經測試的線上改動即可摧毀既有的安全與準確度防線。

為解決上述挑戰，本白皮書提出 **EARA-7（Enterprise Agent Reference Architecture）企業級智能體七層參考架構**，並將其映射為職責邊界清晰的**五大治理象限**，為跨行業組織提供一套可複用、可審計、可規模化擴展的標準工程藍圖。

## 2. 企業級智能體工程成熟度演進模型

在進入具體分層規範前，企業需明確自身系統所處的工程階段。EARA-7 將企業智能體的演進劃分為四個成熟度等級：

| 成熟度等級 | 架構形態 | 核心能力特徵 | 典型生產環境盲區 |
| --- | --- | --- | --- |
| **Level 1：基礎對話層**<br>

<br>*(Wrapper & Prompting)* | 裸模型 API 封裝與靜態系統提示詞 | 具備基礎語言理解與品牌語氣控制能力 | 缺乏私有知識接地（Grounding），無法驗證事實真偽，容易產生業務規則幻覺 |
| **Level 2：知識增強層**<br>

<br>*(RAG-Enabled Assistant)* | 檢索增強生成架構（Vector DB + LLM） | 能引用企業內部非結構化文件進行問答 | 僅限「唯讀資訊輸出」，無法與核心業務系統互動以完成端到端任務閉環 |
| **Level 3：自主行動層**<br>

<br>*(Tool-Enabled Agent)* | 透過標準協議（如 MCP）接入內部 API 與工作流 | 具備意圖拆解、跨系統查詢與狀態寫入能力 | 缺乏身份透傳與安全護欄，面臨越權存取、提示詞注入與高併發成本失控風險 |
| **Level 4：企業治理層**<br>

<br>*(EARA-7 Governed Agent)* | 具備零信任安全、動態路由與自動化測評閉環 | 全鏈路可審計、權限細粒度隔離、成本可控且支援持續迭代 | **企業生產環境目標終態（Production-Ready Standard）** |

## 3. EARA-7 七層參考架構詳解

EARA-7 採用「能力演進由內向外、流量防禦由外向內」的雙向設計邏輯。在運行期（Runtime），所有外部請求必須依序穿過外圍的成本調度、安全護欄與權限校驗閘道，方能觸達核心推理與工具執行引擎。

### 3.2 各層級技術規範與職責定義

* **L1 基礎推理與策略層（Inference & Policy Layer）**
* **架構職責**：提供與底層模型供應商解耦的統一推理網關（Model-Agnostic Gateway），並綁定受版本控制的系統級策略（System Policy）。
* **核心組件**：多模型路由代理（支援公有雲 API 與私有化部署開源模型熱切換）、結構化策略模板（定義角色邊界、合規立場與拒答規則）。
* **設計原則**：在生產環境中，裸模型與系統策略必須作為不可分割的原子單元部署，嚴禁無策略約束的裸模型直接暴露於業務介面。


* **L2 領域知識檢索層（Knowledge & Grounding Layer）**
* **架構職責**：將企業內部非結構化知識（規章制度、產品手冊、技術文檔、歷史案例）轉化為可精確檢索的上下文依據，消除事實性幻覺。
* **核心組件**：語意分塊管線（Semantic Chunking）、混合檢索器（向量相似度檢索 + 關鍵字全文檢索）、重排序模型（Reranker）與來源元數據索引。
* **設計原則**：強制執行「無依據不作答（No-Source, No-Answer）」策略；當檢索置信度低於預設閾值時，必須觸發確定性降級或轉交人工處理。


* **L3 標準工具執行層（Tool & Action Layer）**
* **架構職責**：賦予智能體與外部業務系統（ERP、CRM、ITSM、通訊協作平台、資料庫）互動並改變系統狀態的執行能力。
* **核心組件**：基於 **MCP（Model Context Protocol）** 或標準化 OpenAPI Schema 的工具註冊中心、非同步任務執行器、人工審批中斷器（Human-in-the-Loop, HITL）。
* **設計原則**：嚴格實施工具讀寫分離；凡涉及資金撥付、核心資料庫寫入或對外批量發送訊息的高風險操作，必須強制掛起並等待人工確認。


* **L4 身份與權限治理層（Identity & Access Layer）**
* **架構職責**：確保智能體在檢索知識與調用工具時，其資料可見範圍與操作權限嚴格受限於「當前發起請求的終端用戶」。
* **核心組件**：企業身份認證整合（OAuth 2.0 / OIDC）、權限上下文透傳中間件（Identity Passthrough）、RBAC/ABAC 策略執行點。
* **設計原則**：**零提權原則（Zero Privilege Escalation）**——嚴禁為智能體配置全局超級管理員 Service Account 去繞過業務系統原有的存取控制列表（ACL）。


* **L5 雙向安全護欄層（Guardrails & DLP Layer）**
* **架構職責**：在請求進入核心推理前阻斷惡意指令注入，並在響應返回用戶前過濾敏感機密與個人隱私資訊。
* **核心組件**：輸入端提示詞注入分類器（Prompt Injection Classifier）、結構化上下文隔離標籤（區分可信指令與外部非信任數據）、輸出端資料外洩防護引擎（DLP / PII Masking）。
* **設計原則**：預設將所有來自外部郵件、網頁爬蟲、用戶上傳文件及第三方 API 回傳的文本視為**非信任數據（Untrusted Data）**，防止其劫持控制流。


* **L6 流量與成本優化層（Traffic & FinOps Layer）**
* **架構職責**：在高併發與大規模生產調用下，平衡端到端響應延遲（Latency）與推算資源成本（Token Cost）。
* **核心組件**：分散式語意快取（Semantic Cache）、輕量級意圖分類器（Intent Classifier）、多級模型路由器（Tiered Model Router）。
* **設計原則**：遵循「快取優先、小模型兜底、大模型攻堅」的漏斗原則——重複問題由快取毫秒級響應，標準化查詢分流至低成本小模型（SLM），僅將複雜多步推理路由至旗艦大模型。


* **L7 可觀測與品質運維層（Observability & Eval Layer）**
* **架構職責**：提供全鏈路執行透明度，並建立配置變更的自動化回歸測試門禁，保障系統長期穩定演進。
* **核心組件**：分散式鏈路追蹤（基於 OpenTelemetry 標準的 Trace ID 貫穿）、提示詞與配置資產庫（Config-as-Code / Prompt Git）、CI/CD 自動化測評流水線（Golden Dataset Eval Gate）。
* **設計原則**：將 Prompt、切片參數與工具 Schema 視為正式生產代碼管理；任何未通過黃金測試集回歸驗證的變更，嚴禁合併至生產環境。

## 4. 五大治理象限與生產就緒標準

為便於企業在組織架構中明確責任歸屬，EARA-7 的七個技術層級可收斂為相互獨立、完全窮盡（MECE）的**五大治理象限**，分別對接企業內部的不同專業團隊：

### 4.1 五大治理象限與組織職責映射表

| 治理象限 | 納管層級 | 責任歸屬團隊 | 核心治理目標 | 關鍵驗收指標（KPI） |
| --- | --- | --- | --- | --- |
| **象限一：認知與知識象限**<br>

<br>*(Cognitive & Grounding)* | **L1** 基礎推理與策略層<br>

<br>**L2** 領域知識檢索層 | AI 演算法團隊<br>

<br>領域知識管理員 | 確保模型能力解耦、策略邊界清晰，且所有事實陳述具備可驗證的來源依據 | 檢索召回率（Recall）、事實忠實度（Faithfulness）、越界拒答準確率 |
| **象限二：行動與執行象限**<br>

<br>*(Action & Integration)* | **L3** 標準工具執行層 | 業務系統整合團隊<br>

<br>後端工程團隊 | 規範外部系統連接協議，實現唯讀查詢與高風險狀態寫入動作的隔離管控 | 工具調用成功率、Schema 參數解析準確率、高風險動作攔截率 |
| **象限三：安全與合規象限**<br>

<br>*(Zero-Trust & Compliance)* | **L4** 身份與權限治理層<br>

<br>**L5** 雙向安全護欄層 | 資訊安全團隊（InfoSec）<br>

<br>法務與合規部門 | 落實零信任權限繼承、防禦間接提示詞注入，並確保敏感個資與商業機密零外洩 | 零越權存取事件、注入攻擊攔截率、PII 敏感欄位脫敏覆蓋率 |
| **象限四：成本與效能象限**<br>

<br>*(FinOps & Traffic)* | **L6** 流量與成本優化層 | 雲基礎設施團隊<br>

<br>FinOps 成本治理組 | 透過語意快取削峰與大小模型動態分流，控制高併發場景下的延遲與推算成本 | 快取命中率（Cache Hit Rate）、P95 響應延遲、單次會話平均 Token 成本 |
| **象限五：運維與演進象限**<br>

<br>*(LLMOps & Reliability)* | **L7** 可觀測與品質運維層 | 平台工程團隊（Platform）<br>

<br>SRE 與品質保證（QA） | 建立端到端審計日誌與自動化回歸測評門禁，杜絕線上變更引發的系統性退化 | 全鏈路 Trace 覆蓋率、CI/CD 測評攔截準確率、平均故障定位時間（MTTR） |

### 4.2 生產環境強制控制項（Mandatory Engineering Controls）

企業在將任何智能體推向正式生產環境前，必須完成以下五項跨象限強制審計：

1. **【象限一控制項】引用強制與置信度熔斷**：所有基於 L2 知識庫生成的回答，必須在內部上下文中綁定文件版本號與段落標識符；當最高檢索分數低於預設安全閾值時，系統必須自動熔斷生成流程並轉接人工坐席。
2. **【象限二控制項】工具分級註冊與 HITL 閾值鎖定**：所有接入 L3 的 MCP Server 工具必須在元數據中聲明風險等級（`READ_ONLY`、`LOW_IMPACT_WRITE`、`HIGH_IMPACT_WRITE`）；凡標記為高影響寫入的操作，必須由獨立的審批網關強制攔截並驗證人工授權簽章。
3. **【象限三控制項】令牌透傳與雙向過濾**：L4 必須驗證每次工具調用請求均攜帶有效的終端用戶身份憑證；L5 必須在模型輸入前執行結構化邊界標記，並在輸出返回前執行正則與語意雙重 DLP 脫敏掃描。
4. **【象限四控制項】配額熔斷與路由降級**：L6 必須為每個租戶或業務線設定單位時間 Token 消耗上限（Rate Limiting & Budget Cap）；當旗艦大模型出現高延遲或配額告警時，路由層需具備自動切換至備用模型或輕量級降級策略的能力。
5. **【象限五控制項】變更不可變性與測評門禁**：線上環境嚴禁直接手動修改提示詞或檢索參數；所有配置變更必須透過版本控制系統提交，並由 L7 自動觸發包含對抗性測試樣本（Adversarial Cases）與核心業務案例的回歸測評流水線，指標達標後方可自動化發布。

## 5. 跨行業平台複用模式（Platform-Plugin Operating Model）

EARA-7 的核心工程價值在於實現「底座能力平台化、業務場景插件化」，使企業無需為每個部門重複建設基礎設施：

* **企業級共享底座（Shared Platform Core — L1, L4, L5, L6, L7）**：
由中央 AI 平台團隊統一建設並維護。多模型網關、RBAC 身份鑑權、雙向安全護欄、語意快取、模型路由與 CI/CD 測評流水線作為標準基礎設施服務（Infrastructure-as-a-Service）對全公司開放。
* **業務領域插件包（Domain Plugin Packages — L2 + L3）**：
各業務部門只需按照標準規範配置專屬的**領域知識庫索引（L2）**與**領域 MCP 工具集（L3）**，即可在數天內完成合規智能體的組裝與上線：
* **金融與財稅領域**：掛載合規法規庫（L2）+ 帳務查詢與報銷單預審 MCP 工具（L3），結合 L4 嚴格隔離部門財務資料權限。
* **供應鏈與製造領域**：掛載設備維修手冊與庫存規範（L2）+ ERP 庫存查詢與採購補貨工單 MCP 工具（L3），對大額採購寫入啟用 HITL 審批。
* **客戶服務與營運領域**：掛載最新產品政策與售後條款（L2）+ 訂單狀態查詢與標準化退換貨工單 MCP 工具（L3），透過 L6 語意快取扛住促銷高峰併發查詢。
* **人力資源與內部 IT 領域**：掛載員工手冊與 IT 運維知識庫（L2）+ 休假申請與帳號權限開通 MCP 工具（L3），透過 L5 嚴格遮罩薪資與個人隱私欄位。

## 6. 分階段落地路線圖（Phased Implementation Roadmap）

建議企業採取漸進式演進策略，分三個階段完成 EARA-7 標準架構的部署：

1. **第一階段（第 1–4 週）：夯實認知底座與可觀測基礎（L1 + L2 + L7 基礎追蹤）**
建立統一模型網關與 Prompt 版本庫，完成核心業務知識庫的向量化與溯源引用機制，並自第一天起接入全局 `Trace ID` 日誌追蹤，確保所有問答行為有據可查。
2. **第二階段（第 5–8 週）：開放受控工具執行與零信任安全（L3 + L4 + L5）**
基於 MCP 協議分批接入唯讀查詢類工具，同步上線用戶身份上下文透傳（RBAC）與輸入/輸出雙向安全護欄；在驗證安全攔截有效性後，再逐步開放帶有人工審批門禁（HITL）的寫入型工具。
3. **第三階段（第 9–12 週）：規模化成本優化與自動化測評閉環（L6 + L7 CI/CD Gate）**
根據生產環境真實流量日誌建立高頻問題語意快取，訓練輕量級意圖分類器實現大小模型動態路由；同時將歷史高價值真實對話沉澱為黃金測試集，正式啟用 CI/CD 上線前自動化測評門禁。

---

企業級智能體的競爭壁壘，從來不在於單一模型的參數規模，而在於組織將機率性的大語言模型封裝為確定性、可治理工程系統的能力。透過 EARA-7 七層參考架構與五大治理象限的系統化約束，企業得以在釋放智能體自主執行潛力的同時，牢牢守住安全合規、財務成本與系統可靠性的底線，實現跨行業、可規模化複製的數位勞動力轉型。
